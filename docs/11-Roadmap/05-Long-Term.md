# Visão Geral

Este documento define a visão estratégica de longo prazo do MedFlow.

Diferentemente dos documentos:

```text
01-MVP.md
02-v1.md
03-v2.md
04-v3.md
```

este documento não representa uma versão específica do produto.

Seu objetivo é preservar:

- Direction.
- Principles.
- Strategic Intent.
- Architectural Philosophy.
- Product Identity.
- Long-Term Constraints.
- Future Opportunities.
- Decision Boundaries.

A função deste documento é permitir que futuras gerações da Equipe MedFlow compreendam:

```text
Where are we trying to go?

Why are we building MedFlow?

What should remain true
even when the technology changes?
```

---

# Por Que Este Documento Existe

Roadmaps tornam-se progressivamente menos confiáveis quanto maior for o horizonte temporal.

Em 2026 é possível planejar razoavelmente:

```text
MVP

↓

v1

↓

v2
```

É possível imaginar uma direção para:

```text
v3
```

Entretanto, tentar definir detalhadamente:

```text
MedFlow 2030

MedFlow 2033

MedFlow 2036
```

criaria uma falsa sensação de previsibilidade.

Tecnologias mudarão.

Regulações mudarão.

Modelos de AI mudarão.

O mercado mudará.

A medicina mudará.

Os usuários mudarão.

O próprio MedFlow mudará.

Por isso:

```text
Long-Term Vision

≠

Long-Term Feature List
```

# Considerações Finais

O MedFlow não deverá ser construído apenas para funcionar hoje.

Também não deverá ser construído tentando adivinhar exatamente como será o mundo daqui a dez anos.

Esses dois extremos são perigosos.

```text
Only Today

↓

Short-Term Architecture
```

```text
Imaginary Future

↓

Premature Complexity
```

O caminho correto está entre eles.

```text
Solve Today's Problems

+

Preserve Tomorrow's Options
```

Essa deverá ser uma das filosofias centrais do MedFlow.

O projeto deverá continuar evoluindo.

Tecnologias serão substituídas.

Arquiteturas serão modificadas.

Features serão criadas e removidas.

Models de AI serão trocados.

Providers desaparecerão.

Novos mercados surgirão.

Regulações mudarão.

Pessoas entrarão e sairão da equipe.

Mas alguns fundamentos deverão permanecer:

```text
Protect the Patient.

Respect the User.

Preserve Trust.

Keep the Core Reliable.

Measure Before Optimizing.

Document Important Decisions.

Earn Complexity.

Use AI Responsibly.

Build for Change.

Never Stop Learning.
```

O objetivo final não é construir o sistema com a maior quantidade de Features.

Não é possuir a arquitetura mais sofisticada.

Não é utilizar a tecnologia mais recente.

Não é possuir AI em cada tela.

O objetivo é construir um sistema que continue sendo útil, confiável e compreensível enquanto o mundo ao redor dele muda.

```text
MedFlow

should not survive
because its technology
never changes.

MedFlow should survive

because it was designed
to change.
```

Essa é a visão de longo prazo.

O último documento desta pasta:

```text
06-Idea-Backlog.md
```

terá uma responsabilidade diferente.

Ele deverá preservar possibilidades sem transformá-las prematuramente em compromissos de produto.
